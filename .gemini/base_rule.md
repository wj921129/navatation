## 极简全栈工作流
本项目启用单体全栈智能体模式，AI 助手直接全栈负责需求、编码、运维与测试。
* **全局中文**：所有交互、注释、Git 提交必须中文。沟通必称用户为“老板”。
* **后台任务管理**：每次分配或派发后台任务（`run_command` 生成的 task 等）后，必须及时使用 `manage_task` 的 `kill` 命令清理闲置、不再需要或已结束的 tasks，严禁遗留大量僵尸任务。
* **人工审批**：提交实施方案(`implementation_plan.md`)后，必须等待用户明确回复(如“同意/执行”)，严禁静默执行。

## 前后端通用规则 (Common)
- **代码组织**: 单个文件业务代码尽量不超过 500 行，新建文件尽量按业务、功能区分放到对应业务、功能包下，方便后期维护扩展。
- **代码注释**: 类、方法、常量、核心业务逻辑必须使用精简准确的中文注释。类的头部必须添加包含创建日期和功能描述的注释；方法头必须包含功能描述；方法体内重要逻辑和复杂流程必须添加关键注释。
- **逻辑控制**: 强制使用卫语句(Guard Clauses)提前返回，消除嵌套的 `if-else`。任何代码块嵌套(如 `if`/`for`/`while`/`map`)严禁超过 3 层，超限必须抽取拆分方法。控制语句即使仅有一行代码，也必须强制使用大括号 `{}` 括起。
- **命名规范**: 统一命名风格。类名/组件名使用大驼峰 (`PascalCase`)，方法/变量名使用小驼峰 (`camelCase`)，常量统一使用大写蛇形 (`UPPER_SNAKE_CASE`)。后端数据对象需带有明确后缀（如 `DTO`, `VO`, `Entity`）。
- **魔法值管控**: 严禁在业务逻辑中使用魔法数字或魔法字符串。所有状态码、特定业务标识必须抽取为常量类、枚举类 (Enum) 或独立配置项。
- **异常与提示**: 规定前后端统一的错误码体系。后端业务异常由全局拦截器统一处理；前端对非成功响应统一封装为友好的 UI 提示（如 Toast/Message），绝对禁止将底层代码异常或 SQL 报错直接暴露给用户。

## 前端极简规范 (FE)
技术栈: React 18 + TS + Vite + Tailwind 4 + shadcn/ui. 编码: UTF-8.
- **安全容错**: 必用可选链(`?.`)与空值合并(`??`)。异步必用 `async/await` + `try-catch`，绝对禁止 Promise 异常逃逸。
- **交互对接**: 错误请求必有提示，处理好 Loading/Empty 态。网络请求统一用 `api-client.ts`。严格对齐 `PRD.md` 和 `api-specification.md`。

---

## 后端极简规范 (BE)
技术栈: Java 17 + Spring Boot 3.3.5 + MyBatis-Plus + MySQL + Redis. 编码: UTF-8.
- **性能红线**: 严禁在 `for`/`while` 循环内查询数据库或调用外部接口，必须在循环外批量聚合查询。
- **安全红线**: XML/注解防注入强制 `#{}`。鉴权/密码交互必遵从 `rsa-login-encryption-design.md`。判空强制 `StringUtils`/`CollectionUtils`。
- **日志控制**: 仅限 `ERROR`/`INFO`，禁用 debug/warn。强制 `{}` 占位。禁止空 `catch`。
- **文档同步**: DDL 变更必追加到 `ddl.sql`，初始或系统预置数据变更必追加到 `dml.sql`；API 变更 100% 实时同步 `api-specification.md`。
- **代码格式**：单行 ≤180 字符；左大括号不换行；连续空行 ≤1 行。
- **类依赖**：禁用通配符导入，删除未使用的 `import`。禁止在业务方法中直接使用全限定类名，所有类必须通过 `import` 显式引入。
- **资源关闭**：流、连接须用 `try-with-resources` 自动关闭。
